# My POS System

## 1. Общо описание

**My POS System** е уеб базирана POS система, реализирана като един HTML файл с вграден CSS и JavaScript.

Системата позволява:

* управление на меню с продукти и комбо предложения;
* създаване и редактиране на текуща поръчка;
* автоматично изчисляване на стойността;
* потвърждаване и записване на поръчки;
* автоматично генериране на уникален номер на поръчка;
* преглед на историята;
* работа с различни касиери;
* PIN защита;
* зареждане на менюто от Google Sheets;
* записване на поръчките в Google Sheets;
* обобщаване на дневните продажби;
* отваряне на таблицата с данните.

Приложението не изисква отделни CSS или JavaScript файлове. Целият интерфейс и основната логика се намират в един `.html` файл.

---

# 2. Технологии

Системата използва:

* **HTML5** - структура на приложението;
* **CSS3** - интерфейс и визуален дизайн;
* **JavaScript** - цялата клиентска логика;
* **Google Apps Script** - backend за комуникация с Google Sheets;
* **Google Sheets** - база за менюто, поръчките и статистиката;
* **Google Fonts** - Rajdhani и Exo 2.

Основният HTML файл може да бъде хостван чрез GitHub Pages, Netlify, Cloudflare Pages или друг статичен web hosting.

---

# 3. Структура на приложението

Интерфейсът е разделен на три основни части:

### Лява колона - Products

Показва наличните продукти и комбо предложения.

Има два таба:

**🍔 Продукти**

* показва всички стандартни продукти;
* всеки продукт има име, emoji и цена;
* натискането върху продукт го добавя към текущата поръчка.

**⭐ Комбо**

* показва комбо предложенията;
* всяко комбо съдържа име, emoji, цена и състав;
* ако комбото е по-евтино от отделните продукти, системата показва спестената сума.

---

### Средна колона - Current Order

Показва текущата поръчка.

За всеки добавен артикул се показват:

* име;
* количество;
* единична цена;
* обща цена;
* бутон за изтриване.

Количеството може да бъде увеличавано или намалявано.

В долната част се показва общата стойност на поръчката.

Налични са:

**CLEAR ORDER**

* изтрива текущата поръчка.

**CONFIRM ORDER**

* потвърждава поръчката;
* получава номер от backend-а;
* записва поръчката в Google Sheets;
* добавя я в историята;
* изчиства текущата поръчка.

---

### Дясна колона - Order History

Показва последните поръчки, регистрирани в текущата сесия.

За всяка поръчка се показват:

* номер;
* час;
* обща стойност.

Налични са:

**ВИЖДАЙ ТАБЛИЦАТА**

* отваря Google Sheets.

**ПРИКЛЮЧИ СМЯНА**

* зарежда дневно обобщение;
* показва броя поръчки;
* общия приход;
* приходите и броя поръчки по касиер.

---

# 4. PIN защита

При стартиране приложението показва PIN екран.

В момента PIN кодът е:

`1515`

Той се задава в:

```javascript
const POS_PIN = '1515';
```

След правилно въвеждане системата записва:

```javascript
sessionStorage.setItem('pos_unlocked', 'yes');
```

Това означава, че отключването важи за текущата browser сесия.

PIN кодът **не представлява истинска сигурност**, защото се намира директно в HTML файла и може да бъде видян от човек, който има достъп до кода.

---

# 5. Касиери

Всеки компютър може да има собствено име на касиер.

Името се записва в:

```javascript
localStorage
```

с ключ:

```text
pos_cashier_name
```

При потвърждаване на поръчка името на касиера се изпраща към Google Sheets.

Това позволява в таблицата да се вижда кой касиер е направил дадена поръчка.

---

# 6. Google Sheets интеграция

Системата използва Google Apps Script като backend.

Основният URL е:

```javascript
const SHEETS_URL = '...';
```

Frontend-ът изпраща заявки към този URL.

Използваните действия включват:

```text
?action=getMenu
?action=getNextOrderId
?action=getShiftSummary
```

Освен това при запис на поръчка се изпращат параметри като:

```text
orderId
date
time
name
type
qty
price
rowTotal
isLast
total
user
```

---

# 7. Меню

Менюто се зарежда динамично от Google Sheets.

При стартиране се изпълнява:

```javascript
loadMenuFromSheets()
```

която извиква:

```text
?action=getMenu
```

Очакваният отговор съдържа:

```javascript
{
    products: [...],
    combos: [...]
}
```

След това интерфейсът се генерира автоматично чрез:

```javascript
renderProducts();
renderCombos();
```

Това означава, че продуктите и цените могат да бъдат променяни от Google Sheets, без да се редактира HTML файлът.

---

# 8. Продукти

Всеки продукт съдържа:

```javascript
{
    id: 1,
    name: "Burger",
    emoji: "🍔",
    price: 5.99
}
```

Основните свойства са:

| Поле    | Предназначение          |
| ------- | ----------------------- |
| `id`    | уникален ID на продукта |
| `name`  | име                     |
| `emoji` | икона                   |
| `price` | цена                    |

---

# 9. Комбо

Комботата се пазят отделно от стандартните продукти.

Примерна структура:

```javascript
{
    id: 1,
    name: "Burger Combo",
    emoji: "🍔",
    price: 9.99,
    items: [
        {
            productId: 1,
            qty: 1
        },
        {
            productId: 2,
            qty: 1
        }
    ]
}
```

Комбото се записва като **един ред в поръчката**, а не като отделни продукти.

Това позволява например:

```text
Burger Combo x2
```

да бъде отчетено като две комбо предложения.

---

# 10. Номерация на поръчките

При потвърждаване на поръчка системата извиква:

```javascript
reserveNextOrderId()
```

която изпраща:

```text
?action=getNextOrderId
```

към Google Apps Script.

Идеята е backend-ът да резервира следващия номер централно.

Това е важно при използване от няколко компютъра, защото локалният JavaScript не трябва да определя номера сам.

Пример:

```text
Компютър A → получава #152
Компютър B → получава #153
Компютър A → получава #154
```

Така се избягва дублиране на номера.

---

# 11. Записване на поръчките

След получаване на номера системата създава snapshot на текущата поръчка.

Всеки продукт се преобразува в ред с информация за:

* номер на поръчката;
* дата;
* час;
* продукт;
* тип;
* количество;
* единична цена;
* стойност на реда;
* обща стойност;
* касиер.

При последния ред се задават:

```text
isLast = true
total = общата стойност
```

Това позволява backend-ът да разпознава края на дадена поръчка.

---

# 12. Опашка за записване

Системата има собствена queue система:

```javascript
const sheetsQueue = [];
```

Тя предотвратява едновременното изпращане на няколко поръчки.

Поръчките се обработват последователно:

```text
Поръчка 152
↓
записване
↓
Поръчка 153
↓
записване
↓
Поръчка 154
```

Отделните редове на една поръчка също се изпращат последователно.

Между заявките има 200 ms пауза.

---

# 13. Lock система

Докато поръчката се записва, интерфейсът се заключва чрез:

```javascript
document.body.classList.add('locked');
```

Това предотвратява:

* двойно натискане на Confirm;
* промяна на поръчката по време на запис;
* изпращане на една поръчка няколко пъти.

На екрана се показва:

**„Обработва поръчката...“**

След приключване заключването се премахва.

# 14. Статус бар

* текущият брой артикули;
* текущата стойност;
* часовник;

Часовникът се обновява всяка секунда.

# 15. Важна забележка за текущия код

В края на HTML файла има функция:

```javascript
function getMenuFromSheet() {
    var menuSheet = SpreadsheetApp.getActiveSpreadsheet().getSheetByName('Меню');
    ...
}
```

`SpreadsheetApp` **не съществува в браузъра**.

Това е Google Apps Script API и може да се използва само в Apps Script проекта, не директно в HTML/JavaScript кода на клиента.

В момента тази функция не се извиква от frontend-а, така че сама по себе си не пречи на работата. Но логически тази функция трябва да бъде преместена в Google Apps Script backend-а.

Правилната архитектура е:

```text
HTML / Browser
       │
       │ fetch()
       ▼
Google Apps Script
       │
       ▼
Google Sheets
```

а не:

```text
HTML / Browser
       │
       └── SpreadsheetApp ❌
```

# 17. Хостване

Тъй като frontend-ът е един HTML файл, той може да бъде публикуван чрез:

* GitHub Pages;
* Cloudflare Pages;
* Netlify;
* друг статичен web hosting.

Google Sheets и Google Apps Script остават отделни от хостинга.

Например:

```text
https://username.github.io/my-pos/
```

зарежда POS интерфейса, а той комуникира с:

```text
Google Apps Script
        ↓
Google Sheets
```

Това позволява няколко компютъра да използват един и същ POS интерфейс и общ backend.

---

# 18. Текущи ограничения

Текущата версия има няколко важни ограничения:

1. Историята в дясната колона се пази само в паметта на текущата страница. При refresh тя се губи от интерфейса.

2. Историята не се зарежда автоматично от Google Sheets при стартиране.

3. PIN кодът е видим в HTML файла и не е подходящ за реална security система.

4. Името на касиера се пази локално на конкретния браузър.

5. Google Sheets се използва като база данни, което е удобно за малък POS, но има ограничения при много голям брой заявки.

6. `getMenuFromSheet()` съдържа frontend код, който използва `SpreadsheetApp` и трябва да бъде в Apps Script backend-а.

7. Записването чрез `Image()` е workaround за изпращане на GET заявки. По-чисто решение би било backend API с правилно обработване на заявките.

---

# 19. Предназначение

Системата е предназначена за малък физически обект, в който няколко касиери могат да използват общ POS интерфейс.

Основната цел е:

**Един интерфейс → общо меню → обща номерация → обща история → централен запис в Google Sheets.**

Текущата архитектура вече позволява основата за работа от няколко компютъра. Най-същественото следващо подобрение е историята в POS-а да се зарежда директно от Google Sheets, вместо да съществува само локално в браузъра.
